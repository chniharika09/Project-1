# Student Attendance Management System

A beginner-friendly, database-backed college attendance website. Teachers sign in, manage students and subjects, record attendance by subject and date, and view/download percentage reports.

## Problem, objectives and users
Paper registers make it difficult to correct entries, locate attendance by subject, and calculate attendance percentages. This app keeps records in Supabase PostgreSQL. Only explicitly authorized teacher accounts can access the system. Students are managed as records and do not have login accounts in this MVP.

### Features
- Teacher login via Supabase Auth; backend verifies every token and an email allowlist.
- Add, search, edit and delete students; unique roll numbers.
- Add and delete subjects; unique subject names.
- Mark Present or Absent for each student on a given date and subject; resaving updates records instead of duplicating them.
- Per-subject attendance percentages (Present / Total marked sessions x 100), CSV export.
- Responsive interface, server-side input validation, restricted database access.

### Limitations
- A single institution-wide teacher role; no per-class teacher assignment or student accounts.
- Deleting a student/subject permanently deletes related attendance.
- Dates are selected by the teacher; there is no timetable, holiday calendar, or period-level attendance.
- A newly added student has no historical attendance until marked. Unmarked sessions are not counted as absent.
- Requires internet access and a Supabase project. The app is not deployed automatically.

## Technology and architecture
HTML5, CSS3 and browser JavaScript in `frontend/`; Node.js/Express in `backend/`; Supabase Auth and PostgreSQL database; Git/GitHub for version control.

Browser -> Supabase Auth (login) -> browser receives short-lived access token -> Express API verifies token and teacher allowlist -> Supabase PostgreSQL (server secret key). The frontend never receives the server secret key.

## Requirements and installation (Windows)
Install [VS Code](https://code.visualstudio.com/), [Node.js LTS](https://nodejs.org/), and [Git](https://git-scm.com/). In a new VS Code terminal (PowerShell), check:
```powershell
node --version
npm --version
git --version
```
Extract this ZIP, open its `student-attendance-management-system` folder in VS Code, then:
```powershell
cd backend
npm install
```
`npm install` creates `node_modules` and a lockfile; the ZIP may already include the lockfile. If PowerShell blocks `npm`, run `npm.cmd install` instead.

## Create the database and authentication
1. Open [Supabase](https://supabase.com/) and create a free project. Wait until it is ready.
2. Open **SQL Editor**, paste all of `database/schema.sql`, click **Run**. In **Table Editor**, verify `students`, `subjects`, and `attendance` exist.
3. Under **Authentication -> Users**, create a teacher user with an email and a strong password (or use an approved invitation flow). Confirm the user's email as appropriate for your Supabase settings.
4. Under **Project Settings -> API Keys** (wording may vary), locate your project URL, public publishable/anon key and secret/service-role key. The secret key is for the server ONLY.
5. In `backend/`, copy `.env.example` to `.env` and fill your actual values. Set `TEACHER_EMAILS` to the email of your created teacher. Multiple teacher emails can be separated by commas. Do not include spaces inside email addresses.
6. In `frontend/`, copy `config.example.json` to `config.json`. Replace the sample URL and key with the SAME project URL and the public publishable/anon key (never the secret key).
7. Check the Auth configuration permits email/password sign-in.

Sample **backend/.env** (replace all placeholder values):
```dotenv
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_ANON_KEY=YOUR_PUBLIC_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SECRET_KEY
TEACHER_EMAILS=teacher@example.com
```
The server key must never be pasted into `frontend/config.json`, a website, or GitHub. `.env` is private; `.env.example` is safe to share. RLS is enabled for all tables and no public policies are granted; the server's privileged client bypasses RLS **only after** Express validates the teacher's identity. Do not reuse this privileged client in unauthenticated routes.

## Start the application
From `backend/` in a VS Code terminal:
```powershell
npm start
```
Expected message: `Attendance app: http://localhost:3000`.
Open **http://localhost:3000** in your browser. Sign in with your teacher account. The frontend is served by Express; do not open `index.html` directly from File Explorer. A working `/api/health` returns `{ "ok": true }` (this alone does not prove the database is connected).

## How to use
1. **Students:** add student name, unique roll number and class. Search, edit or delete as needed.
2. **Subjects:** add Mathematics, Physics, etc.
3. **Mark attendance:** choose a date and subject, click Load, select Present/Absent for every listed student, then Save.
4. **Reports:** select a subject, click Generate report, and optionally Download CSV. A student with 0 recorded sessions displays N/A instead of 0%.

## API endpoints
All endpoints except health require `Authorization: Bearer <Supabase access token>` and an email listed in `TEACHER_EMAILS`.

| Method | Route | Request | Success | Common errors |
|---|---|---|---|---|
| GET | `/api/health` | none | `{ok:true}` | — |
| GET | `/api/students` | none | student array | 401,403,503 |
| POST | `/api/students` | JSON `{name,roll_no,class_name}` | created student, 201 | 400,401,403,409 |
| PUT | `/api/students/:id` | same JSON | updated student | 400,404,409 |
| DELETE | `/api/students/:id` | none | `{ok:true}` | 400,404 |
| GET | `/api/subjects` | none | subject array | 401,403 |
| POST | `/api/subjects` | JSON `{name}` | created subject, 201 | 400,409 |
| DELETE | `/api/subjects/:id` | none | `{ok:true}` | 400,404 |
| GET | `/api/attendance?date=YYYY-MM-DD&subject_id=1` | query parameters | `{student_id,status}[]` | 400 |
| POST | `/api/attendance` | JSON `{date,subject_id,records:[{student_id,status}]}` | `{ok:true,count:N}` | 400,503 |
| GET | `/api/report?subject_id=1` | query parameter | student rows with present,total,percentage | 400,503 |

The attendance `POST` is an upsert. Every student ID must exist, each ID can appear only once in the submitted list, and status must be exactly `Present` or `Absent`. Database unique constraints prevent duplicate student/subject/date records. Attendance is saved in batches of up to 500 students per request. Database failures return a generic message rather than leaking credentials.

## Manual testing
| Test | Expected result |
|---|---|
| Open `/api/health` | `{ok:true}` |
| Sign in with approved teacher email | Dashboard opens |
| Sign in with an account not in `TEACHER_EMAILS` | 403 teacher-only message |
| Access private API without a token | 401 |
| Add student and refresh | Student remains in database |
| Add duplicate roll number | 409 error |
| Add a subject twice | 409 error |
| Mark Present, save, reload same date/subject | Saved status reappears |
| Change status, save again | One record per student/subject/date, updated status |
| View report | Present, total and percentage are correct |
| Download CSV | CSV contains report rows |
| Submit empty or invalid values | Rejected |
| Delete student or subject | Related attendance removed after confirmation |
| Resize browser to mobile width | Layout remains usable |
| Stop database access or misconfigure key | Safe error message (no secret exposed) |
| Log out | Dashboard closes; private requests require login |

You must run these checks with your own Supabase project. They have not been verified against a live Supabase instance in this package.

## Troubleshooting
- **Missing configuration:** create `frontend/config.json` from the example; use the public key.
- **Missing environment variable:** create `backend/.env` from the example and restart the server.
- **Invalid login:** check Supabase Auth user, email confirmation and password.
- **Teacher access only:** add the teacher's email to `TEACHER_EMAILS` and restart.
- **Database request failed:** check SQL execution, URL, server key and Supabase project status; inspect the backend terminal for a non-secret error code.
- **Port in use:** change `PORT` in `.env` and restart.
- **No attendance records:** first add students and subjects; click Load before Save.
- **Cannot find npm:** reinstall Node.js LTS, reopen terminal and run `node --version`.

## GitHub upload
Create an empty GitHub repository. In the root project directory, run:
```powershell
git init
git status
git add .
git status
git commit -m "Build student attendance project"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git push -u origin main
```
Replace `YOUR_GITHUB_REPOSITORY_URL` with the actual repository URL. Before committing, verify `backend/.env`, `frontend/config.json`, and `node_modules` are **not** staged. `.env.example` and `config.example.json` should be staged. Never upload real student data or exported database files. If a key was ever committed, rotate it and remove it from Git history; adding `.gitignore` afterward is not enough.
